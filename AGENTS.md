# AGENTS.md

Заметки для будущих сессий по этому репозиторию. Только то, что нельзя
быстро вывести из кода.

## Что это

Telegram-бот для поиска клиентов на услуги по сайтам и автоматизации.
Находит небольшие бизнесы без своего сайта (кафе, бани, барбершопы и т.п.)
через OpenStreetMap, оценивает их по скорингу, генерирует персональное
письмо и показывает владельцу. Рассылка **не** автоматическая — владелец сам
подтверждает отправку. Есть свободный диалог с ботом как с нейросетью.

## Архитектура

- `config.py` — настройки из `.env` через python-dotenv, плюс `PORT` для health.
- `storage.py` — SQLite (`data/leads.sqlite3`): лиды, диалоги, связь диалога с лидом.
- `osm.py` — Overpass API, поиск организаций по категориям и городу.
- `scoring.py` — вес категорий; важный признак — **наличие/отсутствие сайта**.
- `pipeline.py` — discovery → скоринг → подготовка сообщений, экспорт CSV.
- `message_generator.py` — персонализированный текст письма.
- `llm.py` — `build_llm()`: `OpenAICompatibleLLM` (любой OpenAI-совместимый
  endpoint), `Anthropic`, `NoLLM` как заглушка. Провайдер `pollinations` —
  **без ключа** и поддерживает tool calling; он выбран по умолчанию.
- `tools.py` / `agent.py` — `ToolBox` (~10 инструментов) и цикл
  «сообщение → инструменты → ответ» с лимитом шагов. Через них бот правит
  лиды репликами вроде «это не тот контакт».
- `bot.py` — aiogram-хендлеры: команды `/find`, `/ask`, `/reset`, `/help`,
  кнопки на карточках лидов, свободный текст и ответ-реплай на карточку.
- `health.py` — HTTP-сервер `/health`, поднимается только если задан `PORT`.
- `sender.py` — Telethon, полуручная отправка с дневным лимитом.

## Команды

```bash
python3 -m pytest tests/ -q      # тесты
python3 -m smm_bot.bot           # запуск бота
PORT=8080 python3 -m smm_bot.bot # запуск с health-сервером
bash run.sh                      # локальный перезапуск бота
```

## Деплой

- Прод: Render, **Web Service** (не Worker — у воркеров нет бесплатного тарифа),
  тариф Free.
- `render.yaml` — Blueprint. У секретов обязательна пометка `sync: false`,
  иначе Render не спросит их при создании и сервис упадёт с
  `TELEGRAM_BOT_TOKEN не задан`.
- Бесплатный Render засыпает через 15 минут без входящих запросов. Бот сам
  трафик не создаёт, поэтому нужен внешний пинг `/health` раз в 5 минут
  (UptimeRobot) — иначе бот спит и теряет сообщения.
- Бесплатные тарифы на 2026: Render есть, Koyeb есть (засыпает через час),
  Fly.io и Railway — нет.
- Альтернатива без сторонних аккаунтов — `.github/workflows/bot.yml`
  (GitHub Actions, задача до 6 часов, потом перезапуск).
- VPS: `sudo bash deploy/install.sh` — systemd с автозапуском.
- Подробности — `deploy/README.md`.

## Грабли

- **Телеграм отдаёт обновления только одному экземпляру.** Если бот запущен
  одновременно локально и на Render, оба падают с
  `409 Conflict: terminated by other getUpdates request`. Локально лечится
  `pkill -f smm_bot.bot`. Всегда оставляйте ровно один экземпляр.
- **`GITHUB_TOKEN` в этой среде не умеет создавать репозитории** (только пушить
  в существующие). Поэтому репозиторий создаётся вручную, затем
  `bash deploy/push_to_github.sh <имя>`.
- Секреты в git не кладём: `.env`, `data/`, `*.session` в `.gitignore`.
  Перед пушем — проверка в `deploy/push_to_github.sh`.
- **Два экземпляра бота с одним токеном друг друга ломают.** Рабочий бот —
  на Render, но в репозитории есть резервный воркфлоу GitHub Actions
  (`.github/workflows/bot.yml`). Если оба запущены, Telegram отдаёт обновления
  то одному, то другому, а второго убивают прямо во время обработки: владелец
  видит «бот то отвечает, то молчит». Автозапуск по cron у этого воркфлоу
  выключен; включать его можно только погасив Render.
- **`ALLOWED_USER_IDS` молчит, когда не совпадает.** Раньше проверка доступа
  делала тихий `return` — со стороны это «бот не отвечает», хотя процесс жив
  и Telegram опрашивается. Теперь `guard()` отвечает пользователю его ID.
  Если бот молчит — сначала проверьте ID, потом всё остальное.
- **На Render нет доступа к логам без `RENDER_API_KEY`.** Поэтому на старте
  печатаем сводку настроек, а все ошибки хендлеров показываем в чат
  (`@dp.errors`). Не полагайтесь на то, что лог кто-то прочитает.
- **Проверить, работает ли бот, не видя панели хостинга:** длинный опрос
  `getUpdates?timeout=8`. `409 Conflict` = экземпляр живой и опрашивает Telegram.
  `ok` = никто не опрашивает, бот не работает.
- **Какой коммит задеплоен, видно по `/health`.** Отдаём
  `RENDER_GIT_COMMIT` (первые 7 символов) полем `version`. Иначе понять,
  подхватил ли Render пуш, можно только через панель хостинга.
- **На бесплатном Render база пустая после каждого деплоя** — постоянного
  диска там нет. `/health` показывает `leads: 0`, и это нормально: лиды
  набираются заново поиском. Не путать с поломкой.
- **Pollinations без `referrer` не работает.** Отдаёт «reached its budget»
  с HTTP 200, то есть по коду ответа это не видно — распознавать надо по тексту.
  Запрос идёт на `?referrer=...` (`PollinationsLLM`). Не все модели умеют
  вызывать инструменты, поэтому перебираем `openai-fast`, `openai` (`mistral` в API больше нет).
- **Nominatim режет облачные IP** (Render, VPS) и лимитирует 1 запрос/сек.
  Поэтому координаты городов лежат в `smm_bot/geo_cache` и едут в образ,
  а запасной геокодер — Photon. Без этого поиск молча не стартует.
- **Главная причина «бот не находит клиентов» — падеж в названии города.**
  Нейросеть присылает «в Тюмени», а Nominatim на такую форму отдаёт рамку
  нулевой площади → Overpass ищет в точке → 2-3 объекта. Лечится тремя вещами:
  `name_variants()` (перебор основ слова), `bbox_is_usable()` (отсев точки)
  и поиск по вариантам в самом кеше. Не убирайте ни одну из трёх.
- **Ограничение по стране обязательно.** Без `countrycodes=ru` «Казани»
  находится как село Кажани в Македонии, а Photon — как село в Северной
  Македонии (у него проверяем `countrycode`).
- **Неполный ответ Overpass (`remark`) нельзя кешировать.** Однажды он уже
  записал 3 объекта вместо 452, и город «находился» из трёх записей.
- Пересобрать кеш координат: `python scripts/prewarm_geo.py`
  (локально, где Nominatim доступен; ~86 городов, лимит 1 запрос/сек).
- **Показ лидов обязан фильтроваться по городу.** Была жалоба «прошу Саратов,
  а присылает Питер»: `show_next_leads` вызывался с `place=`, но параметр
  игнорировался и брался топ-5 по всей базе — питерские лиды с высоким скором
  перебивали саратовские. Сейчас фильтр есть в `bot.py`, в `ToolBox` и в
  `storage.find_by_city`, который ещё и перебирает падежи (см. ниже).
- **В базе город в именительном падеже, а из чата приходит падеж.**
  `find_by_city("Саратове")` не найдёт строку «Саратов» простым LIKE —
  поэтому `find_by_city` и `geocode` перебирают `name_variants()`.
- **`shown_at`** помечает показанные лиды, чтобы «Следующие лиды» шли дальше.
  Новый поиск по городу сбрасывает отметки (`reset_shown_for_city`), иначе
  лучшие лиды не покажутся заново. Колонка добавляется миграцией в
  `Storage._migrate` — `CREATE TABLE IF NOT EXISTS` её не создаёт.
- При тестах LLM-цикл требует, чтобы фейковый LLM возвращал финальный текст
  при `tools=None` (см. `test_agent_respects_max_steps`).
- **Схема инструмента и поиск должны говорить на одном языке категорий.**
  В `TOOL_SCHEMAS` перечислялись значения тегов OSM (`sauna`, `hairdresser`),
  а `build_query` понимал только ключи пресетов (`banya`, `barber`). Нейросеть
  послушно брала `sauna`, `Overpass` не получал ни одного тега и падал с
  «Пустой список категорий». Модель честно перебирала варианты 5 шагов подряд
  и в конце врала «Готово. Проверьте базу». Отсюда жалоба «снова фигню выдаёт».
  Теперь схема берёт `sorted(osm.CATEGORY_PRESETS)`, а `normalize_categories()`
  переводит и теги OSM, и русские слова («бани», «сауна»).
- **Результат `search_leads` содержит сами лиды, а не только счётчики.**
  Раньше модель делала лишний круг «search_leads → show_leads → ответ»: 40–60 с
  на простой запрос. С готовым списком «найди бани в Саратове» отвечает за 9 с.
- **Нельзя верить тексту модели про успех.** Если инструмент вернул `ok=False`,
  а модель пишет «Готово» — это ложь (см. `_looks_like_success` в `agent.py`).
- **В запасном режиме нельзя советовать `LLM_API_KEY`.** У
  `LLM_PROVIDER=pollinations` ключ не нужен, и такой совет уводил владельца в
  тупик. Показываем настоящую причину сбоя (`reason` в `_fallback`).
- **Бесплатный Pollinations отдаёт 5xx на ровном месте.** Без повторов в
  `OpenAICompatibleLLM.chat` пользователь видел «работаю без нейросети».
  Три попытки с паузой, `max_tokens=1200` (иначе ответ занимает минуту).
- **Ответы модели надо чистить от markdown.** Она шлёт таблицы `|...|` и
  `**жирный**`, а в Telegram это палки и звёздочки — см. `render_answer`.
- **Долгий LLM нельзя ждать молча.** `talk_to_agent` обновляет «Думаю…» каждые
  15 с и сдаётся через `AGENT_TIMEOUT=120`, иначе человек смотрит в пустоту.
- **Категория в базе — тег OSM** (`sauna`), а не ключ пресета. Для интерфейса
  есть `tools.category_label()`: переводит через `CATEGORY_ALIASES` в
  «Баня/сауна». Используется и в карточке лида, и в выдаче поиска.

## Стиль

- Комментарии и тексты для пользователя — по-русски, без канцелярита.
- Комментарий только там, где код неочевиден (инвариант, обходной путь,
  тонкость порядка). Не пересказывать код и не описывать историю правок.
- Тесты без моков там, где можно обойтись реальным кодом (например,
  health-сервер поднимается по-настоящему и опрашивается через HTTP).
