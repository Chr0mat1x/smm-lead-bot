# Деплой: чтобы бот работал 24/7

Выберите один вариант. Первые два — простые и бесплатные на старте, третий —
самый надёжный.

**Важно понимать заранее:** бот должен работать там, где процесс живёт постоянно.
Из среды OpenHands он не переживёт перезапуск — это временная песочница, а не сервер.

---

## Общее для любого варианта

1. В репозитории на GitHub (или в архиве) **не должно быть** файла `.env` — там токен.
   У проекта `.env` уже в `.gitignore`, так что он не залился. Токен задаётся
   в настройках хостинга как переменная окружения.
2. Переменные, которые надо задать на хостинге:
   - `TELEGRAM_BOT_TOKEN` — токен бота
   - `ALLOWED_USER_IDS` — ваш Telegram ID (иначе бот открыт всем)
   - `YOUR_NAME`, `YOUR_CONTACT` — как вас зовут и как с вами связаться
   - `LLM_PROVIDER=pollinations` — бесплатная нейросеть, ключ не нужен
   - `PORT` — только для Render/Railway (они требуют открытый порт)
3. Если планируете копить лиды между перезапусками — нужен постоянный диск
   (volume). Без него база обнулится при обновлении сервиса.

## Шаг 0. Залить код на GitHub

Render и Railway разворачивают из GitHub. Создайте **пустой** репозиторий
на https://github.com/new (без README и .gitignore), затем выполните:

```bash
bash deploy/push_to_github.sh smm-lead-bot
```

Скрипт сам проверит, что `.env` и токены не уйдут в git, и зальёт проект.

## Вариант 1. Render (просто, есть бесплатный тариф)

1. Залейте проект на GitHub.
2. На [render.com](https://render.com) → New → Blueprint → выберите репозиторий.
   Render прочитает `render.yaml`.
3. В разделе Environment добавьте переменные из списка выше.
4. Deploy. Бот поднимется и будет перезапускаться сам.

Тонкости:
- на бесплатном тарифе сервис засыпает без трафика, но боту трафик и не нужен —
  он держит соединение с Telegram, так что обычно не засыпает;
- база на бесплатном тарифе не сохраняется между деплоями — либо переходите
  на платный с диском, либо миритесь с потерей истории.

## Вариант 2. Railway

1. Залейте проект на GitHub.
2. [railway.app](https://railway.app) → New Project → Deploy from GitHub repo.
   Railway увидит `railway.json`.
3. Добавьте переменные окружения.
4. Deploy.

## Вариант 3. Свой VPS (надёжнее всего, ~200 ₽/мес)

Любой сервер на Debian/Ubuntu (Timeweb, Selectel, Hetzner). Дальше — одна команда.

```bash
# на сервере, в папке с проектом
sudo bash deploy/install.sh
```

Скрипт поставит python, скопирует проект в `/opt/smm_bot`, создаст окружение,
включит сервис `smm-bot` с автозапуском и перезапуском при падении.

Управление:

```bash
journalctl -u smm-bot -f        # смотреть логи
systemctl restart smm-bot       # перезапустить
systemctl stop smm-bot          # остановить
```

База лежит в `/opt/smm_bot/data` и переживает перезапуски.

### Через Docker (то же самое, но в контейнере)

```bash
docker compose up -d --build    # запустить
docker compose logs -f bot      # логи
docker compose down             # остановить
```

`restart: unless-stopped` в `docker-compose.yml` поднимает контейнер после
перезагрузки сервера. Данные монтируются из `./data`.

## Что сделать после деплоя

1. Напишите боту `/start` — он должен ответить.
2. Проверьте, что посторонний не пройдёт: с чужого аккаунта бот должен ответить
   отказом (это `ALLOWED_USER_IDS`).
3. Откройте `/health` на Render/Railway — там должен быть `{"status": "ok"}`.

## Если что-то не работает

- **Бот молчит, в логах `ModuleNotFoundError`** — не установились зависимости,
  выполните `pip install -r requirements.txt`.
- **Сервис падает и перезапускается** — смотрите `journalctl -u smm-bot` или
  `docker compose logs`; чаще всего это неверный токен в переменных.
- **Лиды пропадают после деплоя** — нет постоянного диска, см. пункт 3 выше.
- **Два экземпляра бота одновременно** — Telegram отдаёт обновления только одному,
  второй будет молча простаивать. Убедитесь, что не запущены и VPS, и Render сразу.
